# 射击玩法研究库：新版排版

## 设计目标

把长篇动态页转为可以长期积累和反复检索的设计资料库。首屏提供分类、检索和可阅读的案例，长篇拆解在详情中展开。

## 信息层级

| 区域 | 内容 | 作用 |
| --- | --- | --- |
| 深绿侧栏 | 模式、机制、关卡；动态、时间线、收藏 | 区分研究对象与研究工具 |
| 顶栏 | 当前栏目、统一搜索、导出 | 在各类资料之间保持检索和取用路径一致 |
| 栏目标题 | 当前研究对象与一句用途说明 | 让读者理解该栏目回答什么问题 |
| 首页机制入口 | 玩法机制、关卡机制及实际数量 | 从模式浏览进入专项研究 |
| 筛选区 | 核心玩法、游戏、设计主题、LTM 标签、排序、视图 | 支持多条件交叉检索 |
| 卡片区 | 图片或规则摘要、标题、标签、日期或关联数量 | 以可扫描的内容密度帮助选择 |
| 详情 | 规则、设计观察、机制依据、节奏、关联资料、来源 | 从浏览进入阅读，并保留上下文 |
| 采集中心 | 来源覆盖、执行状态、计划流程 | 为后续自动化接入预留真实状态的展示位置 |

## 三类资料的表达

模式使用原有案例图片与一句话规则，回答「整场怎么玩」。玩法机制用规则摘要作为封面，回答「一条规则如何改变决策」。关卡机制使用关联案例的图片，回答「空间如何组织路线与交战」。

机制卡是有来源的分析提炼。每张卡片关联原案例，原模式也展示对应的提炼卡；同一个案例可以支持多个研究角度。

## 六种核心玩法

筛选区第一行提供「全部、BR（大逃杀）、大战场、爆破模式、搜打撤、PVE、其他（休闲）」。第二行选游戏，第三行选设计主题与模式标签。核心玩法是跨游戏的共同分类。

LTM 不单设资料库或一级分类。核心 BR 和限时 BR 一起出现在 BR 下，限时案例在封面右上角显示 LTM，在详情中显示「LTM · 限时模式」。其他核心玩法也可以与 LTM 组合筛选。

数据用 `gameplayTypes` 保存归属，用 `isLtm` 保存限时标记。机制与关卡卡片继承关联案例的归属；真正跨多个核心模式的案例可以多归属，整体资料总数按 id 去重。时间画板以首项归属分轨，LTM 作为节点标签。

模式分类依据已有案例中的规则；限时标记针对记录的版本，不表示当前开放状态。未标 LTM 不等于已确认永久开放。详细边界与维护规则见 README 的「核心玩法与 LTM 标签」。

## 阅读与取用

“发现玩法”与“玩法模式”合并为唯一首页，统一使用 `#modes`；旧 `#explore` 链接会转入首页并保留筛选参数和详情目标。模式库只展示完整模式案例，专项分析保留在玩法机制与关卡机制中。

资料支持核心玩法、游戏、关键词、设计主题与 LTM 叠加筛选；排序可按名称或案例上线时间。默认推荐浏览，首批展示 12 份，可继续加载。列表视图便于快速扫描。

详情保留原始来源、时间说明和设计观察。收藏兼容旧页面，仍仅保存在当前浏览器。Markdown 导出完整详情与原案例链接；Canvas 保留适合画板阅读的摘要。

## 响应式布局

桌面使用固定侧栏与三列卡片；超宽屏增加至四列。中等宽度采用两列；小于 760px 把侧栏收进导航抽屉；小于 440px 使用单列卡片。顶部搜索和游戏筛选在小屏持续可用。

导航抽屉、详情弹窗与分享弹窗支持键盘关闭和焦点管理。图片不可用时使用文字封面，不展示破图。

## 自动采集的后续接入

采集中心已从页面移除；网站改版不创建、停用或修改外部定时任务。

接入时应由任务实际写入最后执行时间、来源覆盖、待审阅数量、成功/失败状态，并保留原文链接、版本区域、上线日期和采集日期的区别。机制提炼仍应通过案例关联保持来源可追溯。
